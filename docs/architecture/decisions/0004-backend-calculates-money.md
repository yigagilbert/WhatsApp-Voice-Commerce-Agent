# 0004 — Backend calculations override LLM-produced amounts

**Status:** Accepted · 2026-10-05

## Context

LLMs are unreliable at arithmetic and can be manipulated. A total the model "says" may differ from
the true total of the items it extracted.

## Decision

- The model extracts _inputs_ (items, quantities, stated unit prices, shipping). It never supplies totals.
- `calculateOrderTotals` (`packages/commerce/src/pricing.ts`) is the only place totals are computed —
  integer arithmetic with overflow and sanity checks.
- If the model reports a total (`claimed_total`), it is compared and any mismatch is surfaced to
  the merchant as a warning and recorded in the audit log; it is never used.
- Prices default to the catalog; a merchant-stated price is honoured but flagged when it differs.
- The summary the merchant confirms is generated by backend code from database values and replaces
  the model's reply verbatim.
- Analytics tools return pre-formatted amounts so the model does not need to calculate.

## Consequences

- The model cannot misstate the amount being confirmed or charged.
- Discount/tax rules must be implemented in code (desirable: they are business rules).
