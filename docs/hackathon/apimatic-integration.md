## What was used instead (and is not APIMatic Context Plugin usage)

For the shipment and dispute work, PayPal API contracts were validated against primary sources:

- PayPal's official OpenAPI specifications (`github.com/paypal/paypal-rest-api-specifications`,
  `checkout_orders_v2.json`, `customer_disputes_v1.json`, retrieved 2026-10-07).
- PayPal's official TypeScript Server SDK `@paypal/paypal-server-sdk` 2.5.0 — its source states it
  is generated by APIMatic. It was read (not installed in the app) to confirm the Orders v2
  tracking request (`OrdersController.createOrderTracking`: `capture_id`, `tracking_number`,
  `carrier`, `carrier_name_other`, `notify_payer`; no `PayPal-Request-Id`). The SDK does not cover
  Disputes v1.

Findings from that review are in [shipment.md](../architecture/shipment.md) and
[disputes.md](../architecture/disputes.md) (e.g. trackers are only `SHIPPED`/`CANCELLED`, tracking
idempotency is on capture ID + tracking number, evidence goes in a multipart `input` part).
